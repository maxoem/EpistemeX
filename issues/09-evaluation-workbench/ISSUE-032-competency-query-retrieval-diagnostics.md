## 1. Problem Statement & Motivation

Downstream utility evaluation measures whether the reconstructed knowledge graph enables researchers to answer competency questions (e.g. *"What law governs gravitational attraction in Keplerian orbits?"*).

Currently, [`RetrievalEvaluationDetail`](packages/episteme-studio/src/episteme_studio/domain/evaluation.py) aggregates retrieval performance into macro averages:
```python
class RetrievalEvaluationDetail(BaseModel):
    mrr: float = 0.0
    hits_at_1: float = 0.0
    hits_at_3: float = 0.0
    hits_at_10: float = 0.0
    ndcg: float = 0.0
    num_queries: int = 0
```

However, **macro numbers do not allow users to debug retrieval failures**:
1. When MRR drops from 0.85 to 0.55, the engineer cannot identify which specific queries failed.
2. The user cannot see the ranked candidate nodes retrieved for a query, their similarity scores, or whether the expected gold node was ranked at position 11 (just missing Hits@10) or completely absent from the graph (extraction omission).
3. The user cannot view the subgraph traversal trace to understand how the retrieval engine navigated from the query seed to the answer.

## 2. Functional Requirements

### 2.1 Domain Schema & Contracts (`episteme_studio.domain.evaluation`)

Define clean Pydantic domain models for per-query retrieval diagnostics:

```python
class RetrievedCandidateItem(BaseModel):
    rank: int
    node_id: str
    label: str
    class_name: str | None = None
    similarity_score: float
    is_gold_target: bool

class CompetencyQueryDiagnosticItem(BaseModel):
    query_id: str
    query_text: str
    target_category: str | None = None
    expected_gold_nodes: list[str]
    retrieved_candidates: list[RetrievedCandidateItem]
    first_hit_rank: int | None = None   # None if not found in top K
    reciprocal_rank: float = 0.0
    hits_at_1: bool = False
    hits_at_3: bool = False
    hits_at_10: bool = False
    failure_mode: str | None = None     # 'omitted_node', 'low_similarity', 'rank_cutoff'

class RetrievalDiagnosticsResponse(BaseModel):
    evaluation_id: str
    total_queries: int
    mrr: float
    hits_at_1: float
    hits_at_10: float
    queries: list[CompetencyQueryDiagnosticItem]
```

### 2.2 Adapter Implementation (`EvaluationAdapter`)
- In `EvaluationAdapter`:
  - Preserve per-query ranking traces generated by `ExtrinsicRetrievalEvaluator` in an evaluation artifact cache `evaluation/retrieval/{evaluation_id}.json`.
  - For each query, match retrieved node IDs against expected target nodes from `stnb_cpm_queries.yaml` (or custom queries YAML).
  - Classify failure modes:
    - `omitted_node`: Expected node does not exist in the predicted graph.
    - `rank_cutoff`: Expected node exists in graph but ranked $> 10$.
    - `low_similarity`: Node ranked in top 10 but semantic score was insufficient.

### 2.3 Studio API Endpoints (`episteme_studio.api.evaluation`)
Expose:
- `GET /api/evaluation/reports/{evaluation_id}/retrieval-diagnostics`
  - Query parameters: `failed_only: bool = False`, `limit: int = 100`
  - Returns: `RetrievalDiagnosticsResponse`

### 2.4 Frontend Integration (`frontend/src/panels/`)
- In `MetricsDrawer.tsx` or a dedicated `CompetencyQueryInspector.tsx`:
  - Display query table with filter toggles: `All Queries`, `Missed Queries (Rank > 10)`, `Hits@1`.
  - Expanding a query displays the top-10 candidate list:
    - Gold targets highlighted in bold green with checkmarks.
    - False retrievals highlighted in gray/red.
    - One-click button: *"Show Subgraph on Canvas"*, which centers the canvas on the query's retrieved nodes and connecting paths.

## 3. Acceptance Criteria

- [ ] `domain/evaluation.py` defines `CompetencyQueryDiagnosticItem` and `RetrievalDiagnosticsResponse`.
- [ ] `GET /api/evaluation/reports/{evaluation_id}/retrieval-diagnostics` returns HTTP 200 with per-query details.
- [ ] Queries missing gold targets correctly calculate `first_hit_rank = None` and `reciprocal_rank = 0.0`.
- [ ] Failure mode classification accurately distinguishes omitted nodes from ranking cutoffs.
- [ ] Unit tests in `test_evaluation_backend.py` verify query ranking calculations and response models.
