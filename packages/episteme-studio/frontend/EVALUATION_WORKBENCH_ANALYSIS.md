## 1. Domain Analysis & Multi-Layered Epistemic Architecture

The evaluation of sovereign knowledge graphs in scientific and philosophical literature goes beyond standard NLP benchmarks. Scientific knowledge graphs (generated by `episteme-pipeline` and measured by `epistemetrics`) encode multi-layered conceptual structures:

```
+----------------------------------------------------------------------------------------------------+
|                                    KNOWLEDGE GRAPH LAYER HIERARCHY                                 |
+----------------------------------------------------------------------------------------------------+
|  LAYER 3 (L3): Formal TheoryNet & Argumentation                                                    |
|  - Theory atoms & Argument Units (ADUs)                                                            |
|  - Inferential relations: SUPPORTS, ATTACKS, UNDERCUTS                                             |
|  - Bourbaki Structuralist quintuples: <Mp, M, Mpp, C, I>                                           |
|  - Diachronic Lakatosian research programmes (Hard-Core Invariance vs. Protective Belt DI)         |
+----------------------------------------------------------------------------------------------------+
                                                  |
+----------------------------------------------------------------------------------------------------+
|  LAYER 2 (L2): Epistemic Ontologies & Semantic Triples                                             |
|  - Named entities, concept taxonomies, and multi-relational triples                                |
|  - Polarity matrices and relational concordance                                                    |
+----------------------------------------------------------------------------------------------------+
                                                  |
+----------------------------------------------------------------------------------------------------+
|  LAYER 1 (L1): Empirical Grounding & Document Layout                                               |
|  - Document structure, token spans, chunks, and citations                                          |
|  - Multimodal anchors: LaTeX mathematical formulas, PDF coordinates, figures, and tables           |
+----------------------------------------------------------------------------------------------------+
```

### Critical Epistemic Failure Modes
A pipeline achieving an $F_1 = 0.88$ on entity extraction can still commit catastrophic philosophical errors:
1. **Polarity Inversions:** Inverting an inferential edge (confusing an `ATTACKS` rebuttal with a `SUPPORTS` lemma), which synthesizes false consensus in controversial scientific debates.
2. **Foundational Bourbaki Omission:** Omitting a single potential model axiom ($M_p$), which mathematically invalidates the entire downstream actual model ($M$) and empirical claims ($I$).
3. **Severe Overconfidence:** Asserting fabricated entities or relations with $99\%$ extraction probability (miscalibrated predictive distributions).
4. **Diachronic Degeneration:** Introducing ad-hoc auxiliary hypotheses across treatise revisions ($T_0 \to T_1 \to T_2$) without increasing empirical content ($DI > 1$).

1. **Persona A (KG Extraction Engineer):** Diagnoses extraction errors, isolates hallucinations, optimizes confidence thresholds ($\tau$), and calibrates predictive uncertainty (ECE/MCE).
2. **Persona B (Computational Epistemologist & Formal Theorist):** Verifies whether the TheoryNet preserves the formal structuralist architecture (Bourbaki model classes, Sneedian empirical claims, Kuhn loss, Quinean web-of-belief consistency, and Lakatosian hard-core invariance).
3. **Persona C (Scientific Benchmark Curator & Domain Expert):** Creates, validates, and maintains gold-standard datasets; adjudicates borderline grey-zone predictions ($\tau \in [0.80, 0.94]$); and exports publication-ready evaluation tables.
4. **Persona D (Downstream RAG Architect):** Validates retrieval against multi-hop competency questions (MRR, NDCG@K), verifies multimodal document grounding, and audits robustness under adversarial noise (OCR typos, synonym drift).

## 3. Core Analytical Use Cases (UC-1 through UC-8)

* **UC-1: Visual Error Triage & Canvas Overlay:** Projecting True Positives (green), False Positives / Hallucinations (red), False Negatives / Omissions (ghost nodes with dashed outlines), and Polarity Inversions directly onto an interactive 2D/3D topological canvas.
* **UC-2: HITL Adjudication & Live Recalculation:** Triaging grey-zone predictions ($\tau \in [0.80, 0.94]$), recording expert decisions (True Positive, False Positive, Schema Alias), and instantly recomputing macro metrics without re-running the extraction pipeline.
* **UC-3: Confidence Calibration & Reliability Diagrams:** Analyzing Expected Calibration Error (ECE), Maximum Calibration Error (MCE), and 10-bin reliability curves to identify overconfident false claims.
* **UC-4: Multimodal Deep Evidence Inspection:** Selecting any extracted entity or relation and inspecting its grounding across text spans, LaTeX formulas, and PDF bounding boxes with Alignment Grounding IoU ($\text{AG\_IoU}$).
* **UC-5: Multi-Run Benchmark Leaderboard & Pareto Frontier:** Plotting pipeline configurations on an interactive 2D/3D Pareto frontier ($F_1$ vs. Bourbaki Tenability $\delta^*$ vs. Cost/Latency) to identify non-dominated architectures.
* **UC-6: Adversarial Noise Robustness & Stress Testing:** Injecting synthetic typographical, synonym, and sentence-shuffling perturbations to calculate Robustness Degradation Factor (RDF) curves.
* **UC-7: Downstream Competency Retrieval Diagnostics:** Evaluating per-query multi-hop ranking performance (MRR, NDCG@10, Hits@K) and pinpointing graph traversal breakdowns.
* **UC-8: Benchmark Catalog Management, Pre-Flight Linting & Academic Export:** Managing gold standards, running integrity linters (DAG acyclicity, dangling edges), and exporting publication-ready LaTeX tables or JSON-LD.

## 5. Critique Evaluation & Refined Engineering Consensus

A rigorous peer review of the preliminary blueprint revealed key theoretical and engineering gaps. Below is the systematic evaluation of each critique item, its proposed remedy, and the finalized architectural resolution.

### 5.1 Algorithmic & Epistemic Gaps

#### Item 1: The Subgraph Isomorphism Problem & Entity Alignment (Sub-View 3.1)
* **Critique:** The canvas assumes a clean 1:1 mapping between predicted and gold nodes. Exact-match alignment causes severe false error explosions due to synonym drift (e.g., *"Quantum Mechanics"* vs. *"Wave Mechanics"*).
* **Proposed Remedy:** Execute a backend reconciliation pass (dense embeddings + graph overlap). If ambiguous ($0.75 < \tau < 0.88$), prompt the user with a modal *before* loading the canvas.
* **Evaluation & Decision:**
  * *Verdict:* **Partially Sound / Remedy Refined.**
  * *Rationale:* The backend dense embedding pass is correct, but blocking the user with an upfront modal is bad UX.
  * *Resolution:* Run reconciliation asynchronously on the backend. Ambiguous entities are rendered with an **Ambiguous Halo** on the canvas, while an unobtrusive, non-blocking **Entity Reconciliation Drawer** in the Canvas HUD enables inline bulk confirmation (`[Approve All High-Confidence]` or `[Resolve Individually]`).

#### Item 2: Error Propagation in Bourbaki Structuralist DAGs (Sub-View 3.2)
* **Critique:** Actual models ($M$) are restrictions of potential models ($M_p$). An extraction failure at the root $M_p$ level mathematically invalidates dependent $M$ and $I$ components. Flat entity counts artificially multiply errors down the hierarchy.
* **Proposed Remedy:** Implement conditional topological penalties. Mask evaluation of dependent nodes whose parent $M_p$ failed, labeling them as structurally orphaned rather than independently failed.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* Abandon flat counting tables. Implement a **Cascading Bourbaki Sunburst / Tree Grid** displaying:
    $$M_p \longrightarrow M \longrightarrow I$$
    Root failures are flagged as `ROOT_CAUSE_OMISSION`, and dependent nodes are marked `CASCADE_MASKED_ORPHAN`.

#### Item 3: Diachronic State Hydration for Lakatosian Dynamics (Sub-View 3.2)
* **Critique:** Embedding a multi-edition degeneration timeline ($T_0 \to T_1 \to T_2$) inside a single-run report breaks context isolation.
* **Proposed Remedy:** Isolate diachronic evaluation from single-run reports. Introduce a dedicated longitudinal job accepting an ordered array of runs.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* The backend already supports `POST /api/evaluation/dynamics/trajectory` with `DynamicsTrajectoryRequest(run_ids=[...])`. Diachronic dynamics is moved out of single-run reports into a dedicated **Longitudinal Research Programmes** comparator accessible from the Leaderboard and Corpus history.

### 5.2 Architectural & Engineering Omissions

#### Item 4: Main-Thread Blocking during Rapid Keyboard Triage (Section C.1 & C.4)
* **Critique:** Computing transitive reductions and reachability metrics on the client during rapid keyboard triage (`[a]`, `[r]`) will freeze the React main thread.
* **Proposed Remedy:** Move recalculation to a client-side Web Worker or WASM binary.
* **Evaluation & Decision:**
  * *Verdict:* **Remedy Rejected / Re-Architected.**
  * *Rationale:* Implementing graph reachability in client Web Workers duplicates Python `epistemetrics` logic, creating synchronization drift and bundle bloat.
  * *Resolution (Optimistic $\mathcal{O}(1)$ Scalar UI + Deterministic Batch Commit):*
    1. Instant keyboard triage (`[A]`, `[R]`, `[S]`) stages decisions locally in `stagedAdjudications` with an immediate $\mathcal{O}(1)$ scalar formula approximation:
       $$\Delta F_1 \approx \frac{TP + 1}{(TP + 1) + \frac{1}{2}(FP + FN)}$$
    2. **No Idle Auto-Debounce:** To support deliberative reading without mid-thought network race conditions or UI lockouts, decisions accumulate in a local buffer with an undo stack (`[U]` / `Cmd+Z`).
    3. Explicit commit: Pressing `Cmd+Enter` (or clicking `[Commit Batch]`) locks and dispatches the staged items to `POST .../adjudicate-and-recalculate`.
    4. Topological graph invariants (Bourbaki cascading completeness, DAG reachability, acyclicity) remain visually flagged as `[Staged Delta Pending]` until the authoritative server RPC returns.

#### Item 5: The "Cold-Start" Benchmark Curation Problem (Page 1)
* **Critique:** Hand-authoring multi-layered scientific knowledge graphs in raw JSON-LD is impractical for domain experts.
* **Proposed Remedy:** Add a "Promote to Gold Standard" action inside the pipeline viewer so experts can correct an automated run and freeze it as a benchmark.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* Implement the **"Golden Pathway"**: Users run the automated pipeline on a text (generating an 80% baseline draft), visually correct errors in the Studio canvas, and click **"Promote to Gold Benchmark"** to freeze the state into the catalog (`v1.0-gold`).

#### Item 6: Multi-Page Spanning in PDF Grounding (Sub-View 3.5)
* **Critique:** Scientific arguments frequently cross page breaks. A single Cartesian bounding box $[x_0, y_0, x_1, y_1]$ fails when a claim spans across pages.
* **Proposed Remedy:** Support a `SpanArray` schema and continuous scroll document viewer.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* Update the contract to:
    ```typescript
    export interface TextSpanCoordinates {
      page: number;
      bbox: [number, number, number, number]; // [x0, y0, x1, y1] normalized
      is_continuation?: boolean;
    }
    ```
    The document reader renders continuous virtual scrolling with SVG highlight overlays crossing page boundaries.

### 5.3 Workflow & UX Disconnects

#### Item 7: Feedback Loop Isolation
* **Critique:** The Evaluation Workbench lacks actionable hooks back to prompt engineering and ontology configuration.
* **Proposed Remedy:** Provide direct hyperlinks from failure diagnostics to the Contextual Inspector for specific entity types and prompts.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* Add **Actionable Epistemic Hooks**:
    * Schema drift $\longrightarrow$ Quick-action `[Add to Schema / Alias]` opens Engine Settings.
    * Entity extraction collapse $\longrightarrow$ `[Tune Prompt in Execution]` routes to Config Editor with the failing text pre-loaded in the prompt preview pane.

#### Item 8: Redundant Job Launching
* **Critique:** Having a separate "Job Launcher Modal" duplicates the existing Execution workbench.
* **Proposed Remedy:** Deprecate standalone evaluation launching and force all evaluation to be a post-processor stage in the Pipeline Composer.
* **Evaluation & Decision:**
  * *Verdict:* **Remedy Rejected / Unified Architecture Adopted.**
  * *Rationale:* Forcing all evaluation through the Pipeline Composer means re-running full LLM extraction from scratch just to evaluate an already-existing graph against a new benchmark.
  * *Resolution (Unified Dual Entry-Point):*
    1. *In-Pipeline Phase:* Support an optional `EvaluationSolver` stage in the Pipeline Composer for automated CI/CD sweeps.
    2. *Post-Hoc Ad-Hoc Evaluation:* Retain the ability to evaluate existing cached run artifacts against newly selected benchmarks in under 2 seconds without LLM re-invocation.

#### Item 9: Dashboard Viewport Density
* **Critique:** Rendering G6 WebGL, multiple ECharts instances, PDF canvases, and virtualized tables simultaneously causes severe DOM bloat and visual noise.
* **Proposed Remedy:** Adopt strict tabbed routing and viewport isolation, rendering only the active analytical sub-workspace.
* **Evaluation & Decision:**
  * *Verdict:* **Accepted in Full.**
  * *Resolution:* Enforce **Zero-Box Sub-Tabbed Viewport Scoping**. The global header and run KPI strip remain persistent, while sub-workspaces are lazy-loaded via React `Suspense`. Only the active sub-workspace is resident in the DOM.
